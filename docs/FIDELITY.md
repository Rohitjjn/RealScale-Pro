# Fidelity: TSX prototype → Compose

`docs/ui-reference/README.md` calls this the running map. It answers one question per screen:
**which prototype file and which captured state does this Compose file have to reproduce, and how
is it verified?**

- **Prototype** — the file under `docs/ui-reference/prototype/src/`.
- **Compose** — the file under `RealSR-NCNN-Android-GUI/app/src/main/java/com/tumuyan/ncnn/realsr/`.
- **References** — `NN-name` stems from `docs/ui-reference/screens/{light,dark}` (`INDEX.md`).
- **State** — where the numbers on screen come from: the store (`ui/state/AppStore.kt`), the
  planner (`core/plan/PipelinePlanner.kt`) or the engine.
- **Verified by** — the strongest check that actually runs. `instrumented` = the emulator job in
  `.github/workflows/build-apk.yml`; `unit` = `app/src/test`; `visual` = screenshot comparison
  against the reference PNG (see § Verification status).

Because this port is at 1:1 token level — same colours, radii, type ramp, spacing, motion
durations — the differences that remain are listed at the bottom, one line each, instead of a
per-screen diff percentage that nobody could keep honest by hand.

## Decisions that differ from the prototype on purpose

1. **Navigation is a list, not a router.** `AppUiState.routes` is the whole navigator
   (`ui/DesignApp.kt`), so back, predictive back and transition direction are one implementation.
   The prototype's `Route` union is preserved as the sealed `Route` type.
2. **Every number is planned, not simulated.** `PipelinePlanner` is a port of `lib/plan.ts` and is
   pinned by `PipelinePlannerGoldenTest` against `tools/plan-vectors` output.
3. **Downloads and upscales are real.** The prototype fakes progress; `ModelRepository` and
   `UpscaleEngine` drive the same percentages. Model downloads run in-process (one transfer at a
   time, cancelled instantly for Pause, resumed from the `.part` files by HTTP Range) instead of
   going through `WorkManager`, whose deferred scheduling read as "nothing downloads" on some
   devices. The Starter Pack ignores "Wi-Fi only" so first-run setup finishes on mobile data too.
4. **Before/after sweep** clips the "before" layer with `Modifier.drawWithContent { clipRect }`
   instead of two absolutely positioned <img> tags (the only layout mechanism Compose lacks).
5. **Text metrics.** StyreneB is substituted by Inter (`res/font/`), so line heights match but
   glyph widths differ by up to ~2 %.

- `compileDebugKotlin` / `compileReleaseKotlin`: green in CI.
- `testDebugUnitTest` (planner golden vectors, model facts, formatter output): green in CI.
- APK packaging and the "≤ 30 MB, zero bundled models" gate: green in CI.
- Instrumented (`RealScaleSmokeInstrumentedTest`): engine extraction, Quick Upscale sheet,
  onboarding → Setup, Starter Pack pause/resume without a toast, and Home → Settings → Model
  Manager, plus the guide's before/after demo, are asserted on an Android 11 ATD emulator.
- Instrumented, real network (`ModelDownloadInstrumentedTest`): the smallest manifest model is
  downloaded end to end — bytes stream, install lands on disk, Pause preserves the partial transfer
  and Resume finishes it instead of restarting. Skipped when the emulator has no route to
  `huggingface.co`, so a sandboxed runner reports an assumption failure rather than a red build.
- Instrumented (`DesignIconInstrumentedTest`): the two permission-screen glyphs `captureToImage()`
  and must contain >150 ink pixels, and every generated Lucide glyph must carry path nodes. This
  caught a real bug: `addPathNodes(str)` only *parses* a path string — called as a bare statement
  inside `path { }` it adds nothing, so all 49 glyphs had empty geometry and every icon in the app
  drew nothing. `design/icons/SvgPath.kt` now replays the nodes through `PathBuilder`.
- Model layer: `api.github.com`-relayed `model-facts` run reports **61 manifest files checked, 0
  problems** against the mirror, and the catalog joins to the manifest through
  `ModelEntry.manifestId` (see `ModelCatalog.byManifestId`), so downloads and the installed-folder
  layout agree.
- Pixel diff per reference PNG: **not implemented.** `tools/visual-diff` does not exist yet; the
  plan is to pair reference ↔ render by the `NN-name` stem. Until then, treat this table's
  "Verified by" column as the honest statement of coverage, and the reference PNGs as the target,
  not as a proof.

## Third pass — responsiveness, toasts, widgets, guide demo

Four defects reported together ("app lag, toast in the wrong place, models won't download or
delete, widgets broken") turned out to share two causes plus a set of local bugs.

### Root cause 1 — the screens never observed the store

Every screen did `val state = store.state.value`. A `StateFlow.value` read is **not** a Compose
snapshot read, so no screen could recompose when the state changed. It only *looked* alive because
`AppStore` has `var` fields, which makes the class unstable, so `HomeScreen(store)` could never skip
and the whole tree was re-executed on every emission of the flow. With 240 MediaStore rows composed
as images in a plain `Row`, that is seconds of blocking work per download tick — the "5 second" mode
switch, the toggle lag and the theme-switch hang were all this one loop.

- `ui/state/StoreState.kt` adds `AppStore.rememberState()` (`collectAsStateWithLifecycle`), and the
  23 direct `.value` reads in the screens now use it.
- `AppStore` is annotated `@Stable`, so a screen whose parameter did not change is skipped.
- `observeCatalog` coalesces pure progress emissions to ~10 fps; structural changes (start, pause,
  install, fail) pass through immediately, so a download row starts moving on the tap frame.
- `refreshDevice()` bumps `AppUiState.deviceRevision` — `device` is a plain field, and `update { it }`
  used to be a no-op that no screen could see.

### Root cause 2 — the Home photo strip composed the whole library

`Home` rendered `state.photos.forEach { PhotoCard(...) }` inside `HorizontalScroll`. It is now a
`LazyRow` capped at 12 cards (`HOME_PHOTO_LIMIT`); the gallery screen keeps the full list in its
`LazyVerticalGrid`. Ordering was also wrong: `mergeImported` sorted on the *string* id, so
`"media:100"` came before `"media:99"`. `PhotoItem.dateTaken` (MediaStore `DATE_ADDED`, or import
time) is now the sort key, newest first, left to right.

### The rest

- **Guide demo.** The first guide slide is a real before/after canvas: `res/drawable-nodpi/
  demo_before.png` + `demo_after.png` (a soft 72 % copy and a sharp original) driven by the same
  `BeforeAfter` slider the result and Quick Upscale screens use, with the same drag/tap handle,
  sweep-in and Before/After pills. `BeforeAfter` now takes `Any` models and renders an `Int` through
  `painterResource` instead of Coil, so the bundled demo cannot depend on an image loader.
- **Toasts.** `RsToastHost` was a wrap-content `AnimatedVisibility` with `padding(bottom = 112.dp)`,
  so the padding was measured against its own small box and the bubble appeared near the top of the
  screen. It is now a full-size host aligned `BottomCenter` with `navigationBarsPadding()` and a
  28 dp gap, drawn above sheets. Colour: new `toast` / `onToast` / `toastLine` tokens — a warm cream
  bubble with warm ink in both themes, never the black `inverse` surface.
- **Model Manager.** The trailing slot was a 96 dp box holding a full text button
  ("Download 291 MB"), so the download icon and half the label were clipped away — the icon really
  was missing, and the clipped area swallowed taps. Each state now gets its own always-visible
  control with a caption: download (size under it), progress + "Tap to cancel", "Retry" for a failed
  transfer with the failure message under the row, delete, or "Too heavy" for a model the device
  cannot run. Delete was additionally invisible because the row never re-read `state.installed`;
  `ModelRow` observes the store now.
- **Widgets.** Two separate problems: both receivers were labelled `@string/app_name` (the picker
  showed two identical entries), and both providers pointed their `initialLayout` *and*
  `previewImage` at the bare medallion, so the launcher drew a logo until the first Glance frame —
  and, when that frame failed, forever. Fixes: distinct labels and descriptions, per-widget
  placeholder layouts (`widget_enhance_initial`, `widget_recent_initial`) that mirror the real
  content, `previewLayout` for the Android 12+ picker, target cells and `minResize*` sizes,
  `SizeMode.Exact` so a resized widget re-composes at its real size instead of keeping the smallest
  layout, strings moved to resources, and `RealScaleWidgetsUpdater` refreshed from `MainActivity
  .onStart` and whenever the recent-creations list changes.
- **Version** 2.1.1 (55) → 2.1.2 (56) → 2.2.0 (57).

## Phase 3 — Home, Result, Models, 3×/5× and widgets

- **Home** is now the import screen. The "Upscale" / "Browse" hero and the entire recent-photos
  strip are gone; the first thing on the page is **"Choose Another Image To Upscale"** with four
  tiles. `Files` uses `ActivityResultContracts.OpenDocument` (`MediaIntents.pickFromFiles`) so the
  user reaches every folder, SD card and cloud provider, while `Gallery` keeps the in-app browser.
  `More` holds exactly two rows: *Paste from clipboard* and *Share from other apps*.
- **Result.** A finished job rewrites the stack to `Route.Result` instead of landing on Home, so the
  user sees what they paid for. "Hold to see original" is removed — the slider already does it — and
  the compare block is now the slider plus one row with a **Full screen** action that opens
  `Route.ResultFull`, a pinch/double-tap zoomable view of the finished file with share. Before Phase
  3 that button pushed the *original* photo's viewer, so the upscale was never shown full screen.
- **Model Manager.** `ModelCatalog` was rewritten against `assets/model_manifest.json`: 14 models
  the shipped ncnn/MNN binaries really load, plus the two Anime4K shader models. `PACKS` is now
  `starter` (2, auto-installed) + `catalog`; the UI renders a **Starter models** section first and
  then All / Photo / Anime over `catalogModels(filter)`. Cards put the name and description on the
  left with a Details chevron, and the download icon, round 0–100 % progress or green check disc on
  the right, size underneath.
- **3× and 5×.** `ModelCatalog.modelScaleFor` picks the factor the weights can run at (4× for
  Real-ESRGAN, 2× for waifu2x, 2/3/4 for SRMD) and `ModelExecutionSpec.modelScale` passes that to
  the binary; the engine then measures the written file and, when it is not `in × scale`, runs one
  `resize-ncnn -m avir-lancir` pass (`PresetCommandResolver.buildResizeCommand`). `Plan.extraResize`
  is gone because the planner no longer needs to special-case 5×.
- **Live tiles** draw the photo desaturated and reveal the colour image tile by tile
  (`drawWithContent` + `clipRect`), with grid hairlines and an amber ring on the active cell; the
  tip block lost its "Tip" eyebrow.
- **Settings.** Privacy section removed; system-bar style is re-applied from the store's theme
  (`MainActivity.applyEdgeToEdge(appDark)`), which fixes invisible status-bar icons in dark mode;
  Send feedback opens `ACTION_SENDTO mailto:userrohitai@gmail.com` prefilled (with a text-share
  fallback and a local copy kept on disk).
- **Widgets.** The Enhance widget gained 2× / 3× / 5× chips; each fires
  `EXTRA_AUTO_SCALE` so the picked image starts upscaling immediately (`AppStore.startWidgetJob`).
  Chips render only when the cell is tall enough (`LocalSize`), and the launcher placeholder mirrors
  them.

## Round 5 — AI Upscale Mode and three root-cause fixes (2.3.0)

- **Result arrival, again.** 2.2.2 fixed the Result screen, not the screen before it. `ProcessingScreen`
  called `store.home()` when the job was null or `photoById` missed (a shared file, a revoked uri — both
  normal for a moment), and `AppStore.onEngineState(Completed)` returned early when the job had already
  been cleared, so *no* navigation ran. Now: no `home()` from Processing, the stack is rewritten even
  with `job == null`, and `observeResults` moves a still-visible Processing screen to the Result as soon
  as the row exists. Three independent paths, all idempotent.
- **Clipboard.** Root cause was in the intake, not the reader: `MediaLibrary.photoFromUri()` called
  `ContentResolver.query()` unguarded, and the clipboard path hands it a `file://` uri (the clip is
  copied into `cache/imports` first), which throws `IllegalArgumentException` — the paste died before
  the screen ever opened. Guarded, mime derived from the name, and `pasteImage()` now reads every clip
  item and every shape: uri, share-intent stream, `content://` / `file://` / absolute path in the text,
  and a browser's HTML `<img src>` (downloaded when remote).
- **Tall images on Config.** `heightIn(max = 320.dp).aspectRatio(ratio)` measured width-first, so a 9:16
  photo produced a 640 dp height, the cap forced the width down to ~180 dp and the whole screen collapsed
  into a column. The preview is a full-width card with `height = (width / ratio).coerceIn(170..320)` and
  `ContentScale.Fit`, and the selected-image facts live in their own `RsGroup` (resolution, size, type,
  aspect).
- **AI Upscale Mode** is a Round-5 product addition with no prototype state to copy, so it borrows the
  prototype's *language* rather than its pixels: the same three-level segmented control, `RsGroup` rows,
  key sheet, `RsBadge`s and the amber sweep (reused from the before/after slider) for the processing
  beam. The on-device modes never upload anything; only this mode uses the network, and only the photo
  being upscaled is sent.
- **Provider transports** are metadata-driven (`core/ai/AiCatalog.kt`) and implemented with
  `HttpURLConnection` (`core/ai/AiImageClient.kt`): OpenAI-style multipart `/images/edits`, Gemini
  `generateContent` with an inline image part, Stability `stable-image/upscale/*`, Replicate predictions
  with polling. Keys are `SharedPreferences` JSON (`core/ai/AiKeyStore.kt`), never uploaded.
- Version 2.2.2 (59) → 2.3.0 (60).
