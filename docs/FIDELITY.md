# Fidelity: TSX prototype → Compose

`docs/ui-reference/README.md` calls this the running map. It answers one question per screen:
**which prototype file and which captured state does this Compose file have to reproduce, and how
is it verified?**

- **Prototype** — the file under `docs/ui-reference/prototype/src/`.
- **Compose** — the file under `RealSR-NCNN-Android-GUI/app/src/main/java/com/tumuyan/ncnn/realsr/`.
- **References** — `NN-name` stems from `docs/ui-reference/screens/{light,dark}` (`INDEX.md`).
- **State** — where the numbers on screen come from: the store (`ui/state/AppStore.kt`), the
  planner (`core/plan/PipelinePlanner.kt`) or the engine.
- **Verified by** — the strongest check that actually runs. `instrumented` = the emulator job in
  `.github/workflows/build-apk.yml`; `unit` = `app/src/test`; `visual` = screenshot comparison
  against the reference PNG (see § Verification status).

Because this port is at 1:1 token level — same colours, radii, type ramp, spacing, motion
durations — the differences that remain are listed at the bottom, one line each, instead of a
per-screen diff percentage that nobody could keep honest by hand.

## Decisions that differ from the prototype on purpose

1. **Navigation is a list, not a router.** `AppUiState.routes` is the whole navigator
   (`ui/DesignApp.kt`), so back, predictive back and transition direction are one implementation.
   The prototype's `Route` union is preserved as the sealed `Route` type.
2. **Every number is planned, not simulated.** `PipelinePlanner` is a port of `lib/plan.ts` and is
   pinned by `PipelinePlannerGoldenTest` against `tools/plan-vectors` output.
3. **Downloads and upscales are real.** The prototype fakes progress; `ModelRepository` and
   `UpscaleEngine` drive the same percentages.
4. **Before/after sweep** clips the "before" layer with `Modifier.drawWithContent { clipRect }`
   instead of two absolutely positioned <img> tags (the only layout mechanism Compose lacks).
5. **Text metrics.** StyreneB is substituted by Inter (`res/font/`), so line heights match but
   glyph widths differ by up to ~2 %.

## Verification status

- `compileDebugKotlin` / `compileReleaseKotlin`: green in CI.
- `testDebugUnitTest` (planner golden vectors, model facts, formatter output): green in CI.
- APK packaging and the "≤ 30 MB, zero bundled models" gate: green in CI.
- Instrumented (`RealScaleSmokeInstrumentedTest`): engine extraction, Quick Upscale sheet,
  onboarding → Setup, and Home → Settings → Model Manager are asserted on an Android 11 ATD
  emulator.
- Model layer: `api.github.com`-relayed `model-facts` run reports **61 manifest files checked, 0
  problems** against the mirror, and the catalog joins to the manifest through
  `ModelEntry.manifestId` (see `ModelCatalog.byManifestId`), so downloads and the installed-folder
  layout agree.
- Pixel diff per reference PNG: **not implemented.** `tools/visual-diff` does not exist yet; the
  plan is to pair reference ↔ render by the `NN-name` stem. Until then, treat this table's
  "Verified by" column as the honest statement of coverage, and the reference PNGs as the target,
  not as a proof.
